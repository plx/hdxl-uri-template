# Draft release notes: HDXLURITemplate 0.1.0

Status: **draft only — untagged, unpublished, and audit-pending**

These notes are prepared for review. Do not publish them until the independent
audit accepts the exact candidate and the maintainer separately authorizes the
version, SHA, residual risks, and publication action.

## Highlights

HDXLURITemplate 0.1.0 is the proposed first Swift package release for parsing
and expanding RFC 6570 URI Templates. It provides:

- RFC 6570 Level 4 parsing and expansion;
- undefined, text, list, and insertion-ordered unique-key association values;
- immutable, reusable, `Sendable` native Swift value types;
- semantic string `Codable` for validated templates;
- structured parse and evaluation errors with privacy-safe defaults;
- complete DocC guidance and compiled public-consumer examples; and
- clean Swift 6.3 CI plus recurring sanitizer, fuzz, concurrency, and scaling
  gates.

## Supported environment

The supported toolchain is Swift tools 6.3 in Swift language mode 6 with Xcode
26.6. Supported deployment targets are iOS, macOS, tvOS, watchOS, visionOS,
and Mac Catalyst 26 or later.

Older Swift toolchains, older Apple OS versions, Objective-C, Linux, and other
non-Apple platforms are unsupported.

## RFC behavior and correctness

The unified conformance gate passes all 270 cases from the byte-faithful
`uri-templates/uritemplate-test` snapshot at
`4171dac22aa67fc710b3f6df308a50bd08552986`: 234 positive examples and 36
controlled negative outcomes. No case is skipped, edited, quarantined, or
marked as an expected failure.

The pre-release remediation corrected:

- literal grammar and the verified apostrophe erratum;
- percent-triplet preservation and malformed-percent fallback;
- Unicode prefix truncation at code-point boundaries;
- rejection of prefix modifiers on list and association values;
- ordered association uniqueness and duplicate-key errors;
- structured parse locations measured in UTF-8 bytes; and
- public error boundaries for semantic expansion and Foundation URL
  construction.

## Public API and migration from pre-release snapshots

This is the first proposed release, but consumers of earlier repository
snapshots must account for intentional pre-`1.0` breaks:

- `Comparable` was removed from `URITemplate`, `URIVariableValue`, and
  `URIVariableValueType`; use domain-owned ordering when needed.
- `URITemplate` encodes as its exact validated source string and reparses when
  decoding. Private AST payloads are unsupported.
- `URIVariableValue` and `URIVariableValueType` are not `Codable`. Persist an
  application-owned DTO, then construct runtime values through the public
  factories.
- `URIVariableValue` adds read-only `textValue`, `listValue`, and
  `associationValue` inspection without exposing mutable storage.
- `URITemplate.ParseError` exposes a semantic `kind` and half-open UTF-8
  `sourceRange`. The former underlying parser error and generic
  `DataValidationError` are removed.
- The incomplete Objective-C wrappers, enum exposure, selectors, copying, and
  archive surfaces are removed. Objective-C callers need an
  application-owned Swift bridge.

The initial `0.x` policy allows incompatible changes in a future minor
release. Patch releases are reserved for backward-compatible fixes, security
remediation, and documentation or build corrections.

## Security guidance

The package expands strings; it does not fetch, authorize, or judge a URI.
Reserved and fragment operators intentionally preserve URI delimiters, so
untrusted values can change rendered URI structure. Applications must:

- validate schemes, hosts, ports, paths, and destinations;
- impose limits on templates, variables, collections, and rendered output;
- distinguish successful string expansion from an authorized Foundation URL;
  and
- avoid logging explicit recovery properties, raw templates, values, or
  rendered URIs without an application-specific privacy policy.

Default parse/evaluation descriptions and bridged `NSError` text are bounded
and payload-free. Report vulnerabilities through GitHub's private
vulnerability-reporting form.

## Concurrency and performance

Templates and values are immutable and `Sendable`. Template storage is a
compiler-checked immutable reference: warm metadata reads are lock-free while
the eight-byte value representation and cheap-copy behavior are retained.

On the recorded Apple M4 Max / Xcode 26.6 / Swift 6.3.3 benchmark, direct
Release parsing took median 4.907 ms for a balanced 1,000-template corpus and
49.201 ms for 10,000 templates in a warm process. Fresh-child medians were
6.546 ms and 54.900 ms. These are machine-specific measurements, not latency
guarantees.

A validated compiled-cache prototype was approximately 3.2–3.8 times slower
than direct parsing in realistic comparisons, increased size and memory, and
did not meet its frozen adoption threshold. No compiled cache ships. Parse
once and reuse templates where practical.

Removing unjustified cross-module inlining kept measured public-client parse,
expansion, hashing, and template Codable workloads within 3.7%, while reducing
the compiled Swift module by 80.3% and the final public-consumer executable by
24.0% in the controlled comparison.

## Known limitations

- The exact candidate still requires the independent production-readiness
  audit before any publication decision.
- The package does not impose application-specific input/output limits or
  destination policy.
- Deterministic candidate fuzzing supplements but does not replace the
  audit's coverage-guided fuzz campaign.
- Objective-C, older Apple systems, older Swift toolchains, and non-Apple
  hosts are unsupported.
- Variable values have no package-owned persistence schema.
- No binary ABI or absolute performance SLA is promised.
- No named adopter canary has been executed; a production consumer must own and
  demonstrate its rollout, telemetry, limits, and rollback.

## Rollback

Before publication, any defect invalidates this candidate and selects a new
SHA. After publication, stop adoption, provide upgrade or security guidance,
advise dependency removal when no known-good release exists, fix forward in a
new patch or minor version, rerun all candidate and audit gates, and withdraw
the hosted release where supported without moving or deleting its immutable
tag.
