## Why 0.1.0

`0.1.0` is the smallest Semantic Versioning version that communicates an
intentional initial public contract without implying `1.0` stability. There
has been no published package version, so no released version is superseded.

During `0.x`:

- a minor version may make incompatible public API, source, behavior, support,
  or serialization changes;
- a patch version is reserved for backward-compatible fixes, security
  remediation, and documentation or build corrections;
- every incompatible change requires changelog and migration guidance;
- only the latest published minor line and its latest patch receive security
  support; and
- `1.0` requires a separately reviewed stability decision.

This is a source package without library evolution. It makes no binary ABI
promise. `URITemplate`'s exact validated string is its supported persistence
format; private parser storage is not. `URIVariableValue` and
`URIVariableValueType` have no persistence format or `Codable` conformance.

## Supported contract

The proposed candidate supports:

- Swift tools 6.3, Swift language mode 6, and Xcode 26.6;
- iOS, macOS, tvOS, watchOS, visionOS, and Mac Catalyst 26 or later;
- native Swift parsing and RFC 6570 Level 4 string expansion;
- undefined, text, list, and ordered unique-key association values;
- immutable `Sendable` templates and values;
- semantic string `Codable` for `URITemplate`;
- structured, UTF-8-offset parse diagnostics and privacy-safe default error
  text; and
- a public Swift consumer, complete DocC documentation, and generated
  Objective-C absence checks.

Older Swift or Apple releases, non-Apple platforms, and Objective-C import or
use are unsupported.

## Known limitations and residual risks

- **Independent audit:** The production-readiness audit has not run. #44 must
  produce an acceptable verdict before publication.
- **Fuzzing method:** Deterministic fuzz is not coverage-guided fuzz. The
  independent audit owns its separately budgeted coverage-guided campaign.
- **Production canary:** No named production adopter or canary exists.
  Package-level preparation marks execution not applicable; a load-bearing
  adopter must populate and exercise the canary/rollback template.
- **Resource policy:** The package does not bound caller-sized input and
  output. This is intentional application-owned policy; callers must impose
  limits.
- **Destination policy:** Expansion does not authorize or dereference a URI.
  Callers must validate schemes, hosts, destinations, and use context.
- **Delimiter preservation:** Reserved and fragment expansion can preserve
  delimiters from values. This is intentional RFC behavior; trust-boundary
  guidance is mandatory.
- **Sensitive recovery context:** Explicit error recovery properties and
  value/template reflection can contain sensitive data. Default diagnostics
  are bounded and redacted; applications own recovery-data logging policy.
- **Supported environments:** Objective-C, older Apple systems, older Swift,
  and non-Apple hosts are unsupported by deliberate initial scope.
- **Pre-1.0 evolution:** `0.x` minors may break source or serialization
  contracts with migration guidance; patch releases stay
  backward-compatible.
- **Performance portability:** Benchmarks are machine-specific and no
  absolute latency SLA exists. Preserve raw evidence and remeasure
  representative adopter workloads.

There is no accepted unresolved critical or high implementation finding. Any
such audit finding invalidates the candidate.

## Rollback, withdrawal, and follow-up

Before publication, rollback means stopping: do not tag, do not publish, reopen
DOC-06, fix forward, and validate a new SHA from the beginning.

After publication:

1. stop recommendations and automated adoption of the affected version;
2. publish appropriate upgrade or security guidance without disclosing private
   report content prematurely;
3. advise consumers to pin a last known-good release or remove the dependency;
   `0.1.0` has no earlier supported release;
4. fix forward as `0.1.1` when backward-compatible or `0.2.0` when the public
   contract must break;
5. repeat candidate preparation and independent audit;
6. mark an unusable hosted release withdrawn or yanked where supported, but do
   not move, replace, or silently delete its immutable tag; and
7. require a named adopter to demonstrate its feature flag, dependency pin, or
   removal path with the [canary template](Canary-and-Rollback-Template.md).

Security incidents follow [`SECURITY.md`](../../SECURITY.md). Ordinary
follow-up defects receive linked issues with severity, owner, target version,
and candidate-invalidating disposition.
